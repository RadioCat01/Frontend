## Architecture Overview

EnhanzerAPI is a **layered ASP.NET Core 8 Web API** with clear separation of concerns:

```
┌─────────────────┐
│   Controllers   │  HTTP endpoints & request routing
├─────────────────┤
│    Services     │  Business logic & external API integration
├─────────────────┤
│      DTOs       │  Data contracts between layers
├─────────────────┤
│   Data/Models   │  Database entities & persistence
├─────────────────┤
│   SQL Server    │  LocalDB persistence
└─────────────────┘
```

## Data Layer

### **AppDbContext.cs** (Data/AppDbContext.cs)

**Purpose:** Entity Framework Core DbContext that manages all database operations.

**What it does:**
- Inherits from `DbContext` to provide ORM capabilities
- Defines `DbSet<LocationDetail>` - represents the Location_Details table
- Maps the LocationDetail entity to the "Location_Details" table name in the database
- Handles connection pooling and database context injection

**Key Components:**
```csharp
public DbSet<LocationDetail> LocationDetails { get; set; }
// Represents the Location_Details table in the database

modelBuilder.Entity<LocationDetail>().ToTable("Location_Details");
// Maps the C# class to the actual SQL table name
```

**How it's used:**
- Injected into services and controllers via dependency injection
- Used to query/insert/update/delete LocationDetail records
- Example: `_dbContext.LocationDetails.ToList()` - retrieves all locations

## Models

### **LocationDetail.cs** (Models/LocationDetail.cs)

**Purpose:** Database entity that represents a physical location/branch where purchases occur.

**Properties:**
| Property | Type | Purpose |
|----------|------|---------|
| `Id` | `int` | Primary key, auto-generated by database |
| `LocationCode` | `string` | Unique identifier for the location (e.g., "LOC001") |
| `LocationName` | `string` | Display name for the location (e.g., "Main Branch") |

**Example Data:**
```
Id=1, LocationCode="LOC001", LocationName="Main Branch"
Id=2, LocationCode="LOC002", LocationName="Mumbai Warehouse"
Id=3, LocationCode="LOC003", LocationName="Delhi Hub"
```

**Where it comes from:**
- Created by AuthService when user logs in
- Fetched from external API's response
- Stored in Location_Details table for quick access

## Data Transfer Objects (DTOs)

DTOs are lightweight classes that carry data between API layers. They protect the database model from direct exposure and define contracts for API communication.

### **1. Authentication DTOs**

#### **LoginRequestDto.cs**
**Purpose:** Client sends this to login.

**Request Example:**
```json
{
  "email": "user@example.com",
  "password": "mypassword123"
}
```

**Properties:**
| Property | Type | Required | Description |
|----------|------|----------|-------------|
| `Email` | string | ✅ | User's email (used as username) |
| `Password` | string | ✅ | User's password |

---

#### **LoginResponseDto.cs**
**Purpose:** API returns this after successful login.

**Response Example:**
```json
{
  "success": true,
  "token": "eyJhbGciOiJIUzI1NiIs...",
  "message": "Login successful",
  "locations": [
	{ "locationCode": "LOC001", "locationName": "Main Branch" },
	{ "locationCode": "LOC002", "locationName": "Mumbai Warehouse" }
  ]
}
```

**Properties:**
| Property | Type | Description |
|----------|------|-------------|
| `Success` | bool | Whether login succeeded |
| `Token` | string | JWT token for authenticated requests |
| `Message` | string | Success/failure message |
| `Locations` | List<LocationDetailDto> | User's available locations |

### **2. Location DTOs**

#### **LocationDetailDto.cs**
**Purpose:** Lightweight location data sent to client (doesn't expose database ID).

**Properties:**
| Property | Type | Description |
|----------|------|-------------|
| `LocationCode` | string | Location code (e.g., "LOC001") |
| `LocationName` | string | Location display name |

**Why separate from Model?**
- Model has `Id` (internal database concern)
- DTO doesn't expose `Id` (API contract concern)

## Services

Services contain the **business logic** and encapsulate complex operations.

### **1. AuthService.cs** (Services/AuthService.cs)

**Purpose:** Handles user authentication by calling external API and managing user sessions.

**Implements:** `IAuthService` interface

**Key Method:** `LoginAsync(string email, string password)`

**What happens step-by-step:**

1. **Build External API Request**
   ```csharp
   var request = new ExternalApiLoginRequest
   {
	   API_Action = "GetLoginData",
	   Device_Id = "D001",
	   Sync_Time = "",
	   Company_Code = email,           // Email as company code
	   API_Body = new ApiBody
	   {
		   Username = email,
		   Pw = password
	   }
   };
   ```

2. **POST to External API**
   ```csharp
   var response = await _httpClient.PostAsync(
	   "https://ez-staging-api.azurewebsites.net/api/External_Api/POS_Api/Invoke",
	   jsonContent
   );
   ```

3. **Parse Response**
   - Deserialize JSON response to `ExternalApiLoginResponse`
   - Check if login was successful (ResponseCode == true)
   - Extract user locations from `User_Locations` array

4. **Persist Locations to Database**
   ```csharp
   // Clear existing locations for this session
   _dbContext.LocationDetails.RemoveRange(_dbContext.LocationDetails);
   await _dbContext.SaveChangesAsync();

   // Insert new locations
   _dbContext.LocationDetails.AddRange(locations);
   await _dbContext.SaveChangesAsync();
   ```

5. **Return Result**
   - Returns `AuthServiceResult` with Success flag, Message, and Locations list

**Error Handling:**
- **HttpRequestException:** Network errors
- **JsonException:** Invalid API response format
- **General Exception:** Unexpected errors

All exceptions are caught and logged; clean error messages are returned (no stack traces to client).

**Dependencies Injected:**
- `HttpClient` - for external API calls
- `AppDbContext` - for database access
- `ILogger<AuthService>` - for logging

---

### **2. TokenService.cs** (Services/TokenService.cs)

**Purpose:** Generates JWT (JSON Web Tokens) for authenticated requests.

**Implements:** `ITokenService` interface

**Key Method:** `GenerateToken(string email)`

**What it does:**

1. **Read JWT Configuration**
   ```csharp
   var jwtKey = _configuration["Jwt:Key"];        // Signing secret
   var jwtIssuer = _configuration["Jwt:Issuer"];  // "EnhanzerApi"
   ```

2. **Create Security Key**
   ```csharp
   var key = Encoding.ASCII.GetBytes(jwtKey);
   var securityKey = new SymmetricSecurityKey(key);
   ```

3. **Build Token Claims**
   ```csharp
   Subject = new ClaimsIdentity(new[]
   {
	   new Claim(ClaimTypes.Email, email)  // Embed user email in token
   })
   ```

4. **Set Token Expiry**
   ```csharp
   Expires = DateTime.UtcNow.AddHours(1)  // Token valid for 1 hour
   ```

5. **Sign Token**
   ```csharp
   SigningCredentials = new SigningCredentials(
	   securityKey, 
	   SecurityAlgorithms.HmacSha256Signature
   );
   ```

6. **Return Encoded JWT**
   ```
   eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiJwYXVsQGV4YW1...
   ```

**JWT Token Format:** 
```
Header.Payload.Signature
```
- **Header:** Algorithm (HS256) and type (JWT)
- **Payload:** Claims (email, expiry, issuer, audience)
- **Signature:** HMAC SHA-256 hash of header+payload using secret key

**Dependencies Injected:**
- `IConfiguration` - to read Jwt:Key and Jwt:Issuer from appsettings.json

## Controllers

Controllers handle **HTTP requests** and route them to appropriate services.

### **1. AuthController.cs** (Controllers/AuthController.cs)

**Route:** `/api/auth`

**Endpoints:**

#### `POST /api/auth/login`

**Purpose:** Authenticate user and return JWT token + locations.

**Request Body:**
```json
{
  "email": "user@example.com",
  "password": "password123"
}
```

**Response (Success - 200 OK):**
```json
{
  "success": true,
  "token": "eyJhbGciOiJIUzI1NiIs...",
  "message": "Login successful",
  "locations": [
	{ "locationCode": "LOC001", "locationName": "Main Branch" },
	{ "locationCode": "LOC002", "locationName": "Mumbai Warehouse" }
  ]
}
```

**Response (Failure - 401 Unauthorized):**
```json
{
  "message": "Invalid credentials or network error"
}
```

**What happens inside:**

1. **Validate Input**
   ```csharp
   if (string.IsNullOrWhiteSpace(request.Email) || string.IsNullOrWhiteSpace(request.Password))
	   return BadRequest(new { message = "Email and password are required" });
   ```

2. **Call AuthService**
   ```csharp
   var authResult = await _authService.LoginAsync(request.Email, request.Password);
   ```

3. **Check Success**
   ```csharp
   if (!authResult.Success)
	   return Unauthorized(new { message = authResult.Message });
   ```

4. **Generate Token**
   ```csharp
   var token = _tokenService.GenerateToken(request.Email);
   ```

5. **Map Locations to DTOs**
   ```csharp
   var locationDtos = authResult.Locations
	   .Select(l => new LocationDetailDto
	   {
		   LocationCode = l.LocationCode,
		   LocationName = l.LocationName
	   })
	   .ToList();
   ```

6. **Return Response**
   ```csharp
   return Ok(new LoginResponseDto { ... });
   ```

**Dependencies Injected:**
- `IAuthService` - authenticates user
- `ITokenService` - generates JWT
- `ILogger<AuthController>` - logging

**Security:** `[Authorize]` - **Requires valid JWT token**

**Endpoints:**

**Purpose:** Retrieve all locations for the authenticated user.

**Headers Required:**

**Response (200 OK):**
```json
[

  { "locationCode": "LOC003", "locationName": "Delhi Hub" }
```

**What happens inside:**


**Dependencies Injected:**
- `AppDbContext` - database access

### **3. PurchaseBillController.cs** (Controllers/PurchaseBillController.cs)

**Route:** `/api/purchasebill`

**Security:** `[Authorize]` - **Requires valid JWT token**

**Endpoints:**

#### `POST /api/purchasebill/items`

**Purpose:** Validate purchase bill item and calculate totals server-side.

**Headers Required:**
```
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
```

**Request Body:**
```json
{
  "item": "Flour (10kg bag)",
  "batch": "BATCH001",
  "standardCost": 500.00,
  "standardPrice": 650.00,
  "qty": 5,
  "discountPercent": 10
}
```

**Response (Success - 200 OK):**
```json
{
  "item": "Flour (10kg bag)",
  "batch": "BATCH001",
  "standardCost": 500.00,
  "standardPrice": 650.00,
  "qty": 5,
  "discountPercent": 10,
  "totalCost": 2250.00,
  "totalSelling": 3250.00
}
```

**Response (Validation Error - 400 Bad Request):**
```json
{
  "message": "Quantity must be greater than zero"
}
```

**Validations Performed:**

| Validation | Error Message |
|-----------|---------------|
| Item name is empty | "Item name is required" |
| Batch is empty | "Batch is required" |
| Quantity ≤ 0 | "Quantity must be greater than zero" |
| StandardCost < 0 | "Standard cost cannot be negative" |
| StandardPrice < 0 | "Standard price cannot be negative" |
| DiscountPercent not 0-100 | "Discount percent must be between 0 and 100" |

**Calculations (Server-Side):**
```
TotalCost = (StandardCost × Qty) - (StandardCost × Qty × DiscountPercent ÷ 100)
		  = (500 × 5) - (500 × 5 × 10 ÷ 100)
		  = 2500 - 250
		  = 2250.00

TotalSelling = StandardPrice × Qty
			 = 650 × 5
			 = 3250.00
```

**Why Server-Side Calculation?**
- **Security:** Don't trust client calculations
- **Consistency:** Ensure accurate totals
- **Audit Trail:** Server has authoritative values
- **Frontend:** Can still show estimates, but server validates

**Use Case:**
Angular frontend collects line items, sends to this endpoint for validation and calculation, then displays results to user before final submission.

**Note:** 
No database persistence for purchase items. The frontend maintains the bill table in-memory. This endpoint is purely for validation and calculation.

**Dependencies Injected:**
- `ILogger<PurchaseBillController>` - logging

## Configuration & Setup

### **Program.cs** (Application Startup)

**Purpose:** Configure dependency injection, middleware, and application pipeline.

**Setup Order (Important!):**

1. **Add DbContext**
   ```csharp
   builder.Services.AddDbContext<AppDbContext>(options =>
	   options.UseSqlServer(builder.Configuration.GetConnectionString("DefaultConnection")));
   ```
   - Enables Entity Framework Core with SQL Server
   - Uses connection string from appsettings.json

2. **Add HttpClient**
   ```csharp
   builder.Services.AddHttpClient();
   ```
   - Required for AuthService to make HTTP requests to external API

3. **Register Services**
   ```csharp
   builder.Services.AddScoped<IAuthService, AuthService>();
   builder.Services.AddScoped<ITokenService, TokenService>();
   ```
   - `AddScoped` creates new instances per HTTP request
   - Interfaces enable loose coupling and testing

4. **Configure JWT Authentication**
   ```csharp
   builder.Services.AddAuthentication(options => { ... })
	   .AddJwtBearer(options => { ... });
   ```
   - Validates incoming JWT tokens
   - Checks signature, expiry, issuer, audience
   - Populates `User.Identity` claims

5. **Add CORS Policy**
   ```csharp
   builder.Services.AddCors(options =>
   {
	   options.AddPolicy("AllowAngular", policy =>
	   {
		   policy.WithOrigins("http://localhost:4200")
				 .AllowAnyHeader()
				 .AllowAnyMethod();
	   });
   });
   ```
   - Allows requests from Angular frontend at http://localhost:4200
   - Permits any HTTP header and method
   - Enables cross-origin requests

6. **Add Controllers & Swagger**
   ```csharp
   builder.Services.AddControllers();
   builder.Services.AddEndpointsApiExplorer();
   builder.Services.AddSwaggerGen();
   ```

7. **Configure Pipeline**
   ```csharp
   app.UseSwagger();                    // Enable Swagger UI at /swagger
   app.UseSwaggerUI();
   app.UseHttpsRedirection();           // Force HTTPS
   app.UseCors("AllowAngular");         // Apply CORS policy
   app.UseAuthentication();             // Validate JWT
   app.UseAuthorization();              // Check [Authorize] attributes
   app.MapControllers();                // Route requests to controllers
   ```

**Middleware Order is Critical!**
- CORS must come before authentication
- Authentication must come before authorization
- Mapping controllers must be last

### **appsettings.json** (Configuration)

**Purpose:** Externalize configuration for different environments.

**Sections:**

```json
{
  "ConnectionStrings": {
	"DefaultConnection": "Server=(localdb)\\mssqllocaldb;Database=EnhanzerDb;Trusted_Connection=True;MultipleActiveResultSets=true"
  }
}
```
- **Server:** LocalDB instance on local machine
- **Database:** EnhanzerDb (created by migrations)
- **Trusted_Connection:** Use Windows authentication
- **MultipleActiveResultSets:** Allow concurrent queries

```json
{
  "Jwt": {
	"Key": "this_is_a_very_long_secret_key_for_jwt_signing_that_should_be_at_least_256_bits_long_for_hs256_algorithm",
	"Issuer": "EnhanzerApi"
  }
}
```
- **Key:** Secret used to sign JWT (256+ bits for HS256)
- **Issuer:** Token issuer identifier ("EnhanzerApi")
- Both are read by `TokenService` and JWT configuration in `Program.cs`

## Request/Response Flow

### **Flow 1: User Login**

```
1. Angular Frontend
   └─> POST /api/auth/login
	   {
		 "email": "user@example.com",
		 "password": "password123"
	   }

2. AuthController.Login()
   └─> Validates email & password not empty
   └─> Calls _authService.LoginAsync()

3. AuthService.LoginAsync()
   └─> Builds ExternalApiLoginRequest
   └─> POST to external API (ez-staging-api.azurewebsites.net)
   └─> Parses ExternalApiLoginResponse
   └─> Extracts User_Locations
   └─> Clears Location_Details table
   └─> Inserts new locations into Location_Details
   └─> Returns AuthServiceResult with Success=true, Locations list

4. AuthController (continued)
   └─> Checks authResult.Success
   └─> Calls _tokenService.GenerateToken(email)

5. TokenService.GenerateToken()
   └─> Reads Jwt:Key from appsettings.json
   └─> Creates ClaimIdentity with email claim
   └─> Sets expiry to 1 hour from now
   └─> Signs with HMAC-SHA256
   └─> Returns encoded JWT string

6. AuthController (continued)
   └─> Maps LocationDetail entities to LocationDetailDto
   └─> Returns 200 OK with LoginResponseDto
	   {
		 "success": true,
		 "token": "eyJhbGciOiJIUzI1NiIs...",
		 "message": "Login successful",
		 "locations": [...]
	   }

7. Angular Frontend
   └─> Stores JWT token in localStorage
   └─> Populates locations dropdown
   └─> Ready for authenticated requests
```

---

### **Flow 2: Get Locations**

```
1. Angular Frontend
   └─> GET /api/locations
	   Headers: { Authorization: "Bearer eyJhbGciOiJIUzI1NiIs..." }

2. JWT Middleware
   └─> Validates token signature using Jwt:Key
   └─> Checks token expiry
   └─> Validates issuer and audience
   └─> If valid → proceeds
   └─> If invalid/expired → returns 401 Unauthorized

3. LocationsController.GetLocations()
   └─> [Authorize] attribute verified by middleware
   └─> Queries _dbContext.LocationDetails
   └─> Maps LocationDetail to LocationDetailDto
   └─> Returns 200 OK with array of LocationDetailDto

4. Angular Frontend
   └─> Receives location list
   └─> Populates batch dropdown
```

---

### **Flow 3: Validate Purchase Item**

```
1. Angular Frontend
   └─> POST /api/purchasebill/items
	   Headers: { Authorization: "Bearer eyJhbGciOiJIUzI1NiIs..." }
	   Body: {
		 "item": "Flour (10kg)",
		 "batch": "BATCH001",
		 "standardCost": 500,
		 "standardPrice": 650,
		 "qty": 5,
		 "discountPercent": 10
	   }

2. JWT Middleware
   └─> Validates token (same as Flow 2)

3. PurchaseBillController.ValidateItem()
   └─> [Authorize] attribute verified
   └─> Validates required fields (Item, Batch)
   └─> Validates numeric fields (Qty > 0, costs ≥ 0, discount 0-100)
   └─> Calculates:
	   TotalCost = (500 * 5) - (500 * 5 * 10/100) = 2250
	   TotalSelling = 650 * 5 = 3250
   └─> Sets calculated values in DTO
   └─> Returns 200 OK with updated DTO
	   {
		 "item": "Flour (10kg)",
		 "batch": "BATCH001",
		 "standardCost": 500,
		 "standardPrice": 650,
		 "qty": 5,
		 "discountPercent": 10,
		 "totalCost": 2250,
		 "totalSelling": 3250
	   }

4. Angular Frontend
   └─> Receives validated item with totals
   └─> Displays in purchase bill table
   └─> User can add more items or submit
```

## Key Takeaways

✅ **Layered Architecture:** Each layer has a clear responsibility  
✅ **Dependency Injection:** Services are registered and injected, enabling testing  
✅ **Security:** JWT authentication protects endpoints, server validates inputs  
✅ **Separation of Concerns:** Controllers don't know about databases; Services orchestrate business logic  
✅ **DTOs as Contracts:** API exposes only what clients need; internal models stay internal  
✅ **Error Handling:** All errors caught and logged; meaningful messages returned  
✅ **Configuration-Driven:** Secrets and connection strings in appsettings.json, not hardcoded
